## R04 — Acesso a dados pessoais do profissional

### Identificação do risco

| Campo | Descrição |
| --- | --- |
| ID do risco | `R04` |
| Ameaça de origem | `T04 — Information Disclosure` |
| Caso de abuso relacionado | `CA04 — Acesso a dados pessoais do profissional` |
| Evento de risco | Um usuário autenticado aciona a API de busca ou consulta de profissionais e recebe dados pessoais e sensíveis além do necessário para a operação, permitindo a exposição indevida de informações de um profissional. |
| Causa ou vulnerabilidade | Falta de filtragem de campos na resposta da API, retorno da entidade completa do profissional e ausência de regras de visibilidade que limitem os dados expostos conforme o perfil do usuário. |
| Ativos afetados | Dados pessoais de profissionais, API de busca de profissionais, privacidade dos titulares de dados e conformidade com a LGPD. |
| Consequências | Violação de privacidade, uso indevido dos dados para golpes ou contatos indevidos, danos à reputação do profissional e risco de não conformidade legal com a proteção de dados. |

### Avaliação do risco

| Critério | Valor | Justificativa |
| --- | ---: | --- |
| Probabilidade | `3` | A funcionalidade de busca de profissionais é comum e acessível a usuários autenticados. |
| Impacto | `4` | Dados sensíveis como CPF, endereço, telefone e e-mail podem causar danos graves à privacidade e resultar em golpes, assédio ou responsabilidade legal para a organização. |
| Pontuação | `12` | Resultado de `3 × 4 = 12`. |
| Classificação | Crítico | A pontuação está entre 12 e 16. |

### Estratégia de tratamento

| Campo | Definição |
| --- | --- |
| Estratégia | Reduzir |
| Justificativa | A busca por profissionais é uma funcionalidade essencial, mas o risco pode ser reduzido com controles técnicos de minimização de dados, autorização e monitoramento. |

### Controles propostos e mapeamento NIST CSF 2.0

| ID | Função do NIST CSF 2.0 | Controle proposto | Responsável | Evidência esperada |
| --- | --- | --- | --- | --- |
| `C04.1` | Protect | Implementar retorno de dados mínimos no backend, expondo apenas os campos necessários para a operação de agendamento ou consulta. | Equipe de desenvolvimento | Código ou documentação mostrando o mapeamento de DTOs e a omissão de campos sensíveis. |
| `C04.2` | Protect | Aplicar autorização de visibilidade para limitar o que cada perfil pode ver na API de profissionais. | Equipe de segurança e backend | Regras de acesso documentadas e testes que comprovem a diferenciação de visibilidade por perfil. |
| `C04.3` | Detect | Registrar e auditar acessos à API de profissionais e tentativas de leitura de campos sensíveis. | Equipe de operações | Logs de auditoria e alertas configurados para acessos atípicos a dados pessoais. |
| `C04.4` | Respond | Documentar procedimento de correção e notificação em caso de exposição inadvertida de dados pessoais. | Equipe de segurança e produto | Procedimento formal disponível e exercício de resposta documentado. |

### Ordem de implementação

1. Identificar os campos sensíveis do profissional que não são necessários para a operação de busca.
2. Definir DTOs ou views que retornem apenas os dados estritamente necessários para cada endpoint.
3. Implementar verificações de autorização e visibilidade na API.
4. Adicionar testes que comprovem a omissão de campos sensíveis nas respostas.
5. Configurar logging e auditoria de acessos às rotas de profissionais.
6. Estabelecer o processo de resposta em caso de vazamento de dados e revisar os controles periodicamente.

### Risco residual

| Critério | Valor estimado | Justificativa |
|---|---:|---|
| Probabilidade residual estimada | `1` | A validação rígida de campos e a limitação da visibilidade reduzem significativamente a chance de exposição indevida. |
| Impacto residual estimado | `4` | Mesmo com controles, a exposição de dados pessoais ainda é grave se ocorrer, por isso o impacto residual permanece alto. |
| Pontuação residual estimada | `4` | `1 × 4 = 4`. |
| Classificação residual estimada | Médio | A pontuação estimada 4 está na faixa de 4 a 7. |
| Condição para aceitar o residual | Implementar e validar o retorno mínimo de dados, a autorização de visibilidade e os registros de auditoria. |
| Responsável pela aprovação | Equipe de segurança e arquitetura de dados | As áreas de segurança e arquitetura devem validar a conformidade e a eficácia dos controles. |
| Revisão | Após alterações nos endpoints de profissionais ou nas regras de exposição de dados | Revisar sempre que houver mudanças que afetem a visibilidade dos dados pessoais. |
